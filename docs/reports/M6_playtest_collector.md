### 転生（rebirth / rb-reroll / rb-choose）
- 転生した回数は**延べ28回**。引き直しは **約170回**。
- 採用ラインはだいたい「加算合計が上限の5〜6割」。良い例：ネム姫の3回目（加算合計111/183）、セオの3回目（127/178）、フレイアの2回目（初手72/98）。
- **流した経験**：ウルザ1回目の加算64（技巧+30）、ミラ1回目の加算35（魔力+24・HP+28）、オスカー2回目は回数を絞りすぎて加算9で妥協。

### 良い結果を流したときの気持ち
- 「今回」が「前回」に押し出され、**2つ前は消える**仕組みは `help` に書いてある。それでも連打していると、**「あっ、さっきの方が良かった」と気づいた時にはもう戻せない**。シエラの初手132を失った時は本当に悔しくて、少し引き直しが嫌になった。
- ただ、チケットが余るほどあるので「損した」より「時間を損した」という気持ちが強い。そのうち「良い結果が出たら1回だけ保険で引いて、悪ければprevを取る」という型に落ち着いた。**型ができてからは淡々とした作業になった。**

## 3. 迷った点・分かりにくかった点
1. **見た目がIDでしか表示されない**：`新しい見た目：chr_m_nor_phy_09`、`looks-choose prev|cur で選ぶ` など。`prev` 側（今の姿）は表示もされない。`m/f`・`nor/dem/bea/ugl` から推測するしかなく、何を選んでいるのか分からない。`show` と `roster` にも見た目が出ない。
2. **`rebirth <uid> keep` の挙動**：表示は毎回「新しい見た目：〜」で、維持されているのか分からない。後から見ると、ネム姫は2回目以降も同じID（`chr_m_dem_mag_10`）なので維持はされていたらしい。ただしポーションの減り方が一定しない（7章を参照）。
3. **ギフトの説明がない**：「大食らい」「罠師の勘」「退魔の才」「道案内」の効果が分からない。候補が全員「大食らい」の回では選びようがなかった。転生で「ギフト『大食らい』を獲得」と出ても、良いことなのか分からない。
4. **「加算合計」にHPが入らない**：`HP120(+34/53) ／ 加算合計 44` のように、HPの加算が大きくても合計に入らない。職と関係ない能力（盗賊の魔力など）は合計に入るので、**合計の数字が良し悪しの目安にならない**。ブランの例では「腕力+20・HP+38（加算合計21）」と「腕力+26・HP+1（加算合計33）」で迷った。
5. **加算の上限が能力ごと・人ごとに違う**（`/15`、`/34`、`/114` など）。成長の型と前回の値から決まるらしいが説明はない。数字は増えていくので楽しくはある。
6. **`解錠技術が足りない`**：`status` に `封印の塔×26（解錠技術が足りない）` と出るのに、`open` するとすべて開く。`help` には「解錠技術もここ（expansions）」とあるのに、`expansions` に解錠技術が出てこない。いつの間にか表示が消えた。
7. **装備・転生が「探索中」で拒否される**：`repeat` で回し続けると、変更のたびに `repeat n off` → `wait` → 変更 → `go` → `repeat` の5手順が要る。
8. **`party` で直接入れ替えられない**：`✗ その冒険者は別のパーティにいます`。先に `party 1 3 -` で外す必要がある。
9. **候補の名前が既存メンバーと重なる**：候補に「セオ（盗賊）」「ミラ（盗賊）」「オスカー（魔法使い）」が出て紛らわしい。
10. **`train max` と `train N` は所持金を全部使う**：上限の手前でもお金が尽きるまで回る。1回ずつの費用が大きく伸びるので（Lv1は10G、Lv20前後は4000G、転生後は16000G）、うっかり全財産を使い、修道院の派遣費が払えなかった。
11. **宝箱の演出の基準が分からない**：封印の塔ではレアに「★★★ 演出！」が付くのに、水没神殿や霧の大森林のレアは演出なしの通常行になる。ダンジョンの難度に対して相対的に決まっているように見える。

## 4. 退屈だった点・作業に感じた点
- **引き直しの連打**：1回 = 1コマンドで、結果は数字4〜5個。ループなしでは数百回打つことになる。中盤以降はチケットが無限にあるも同然なので、判断がほぼ「上限の何割か」で済み、ドキドキが薄れた。
- **雇用のステータスがほぼ一様乱数で、職と関係ない**：僧侶でも腕力40・魔力4が普通に出る。「職に合う引き」が出るまでの試行がただ長い（オスカー41回）。
- **転生後のトレーニング**：`train <uid> 20` を全員に打つだけの作業。転生した人数ぶん同じことを繰り返す。
- **宝箱の開封と売却**：1回に最大100個。倉庫300で止まるが、理由は表示されない（`残り41個` だけ）。レア以下は毎回 `sell` でまとめて売る必要があった。`autosell on 2 keep` を入れても、レアや修飾つきが溜まる。
- 長い `wait` の間に連続で撤退している（地下大迷宮で11回連続など）ことに気づきにくい。

## 5. 嬉しかった瞬間・もう1回やりたくなった瞬間
- **ネム姫を合計143で引けた瞬間**：その場で改名してロックした。後の転生3回で、ずっとエースでい続けたのが最高だった。
- **転生の加算で大当たり**：「魔力185(+64/72)」「魔力281(+91/114)・HP98(+35/37)」「腕力157(+53/62)・HP198(+66/79)」。上限に対する比率がひと目で分かるので、当たりがすぐ分かる。
- **転生後のLv22で、転生前のLv40を超えたとき**（ネム姫：攻466 → 472）。転生がちゃんと得になっていると実感できた。
- **宝箱の演出**：「★★★★★ 演出！ レジェンドの宝箱」「★★★★★★ 演出！ **ミシックの宝箱**：退魔のチェインメイル」。星の数で格が分かるのが良い。100個まとめて開けた中に★★★★★が並ぶと気持ちいい。
- **2回目の転生でギフトが増える**（「ギフト『頑健』を獲得」）のは予想外の嬉しさだった。
- ユニークキャラ「★ 白銀のブラン」の加入告知。`rebirth keep` を使おうとして「ユニークキャラの見た目は固定です」と言われたのも、特別扱いらしくて良かった。
- ブサイクだったユリウスが転生で `chr_m_bea_…` になったらしい。見えないのが惜しい。

## 6. 観点への評価
| 観点 | 評価 | 理由 |
|---|---|---|
| 固定の引き継ぎ分とスロット加算分の違いが伝わるか／引き直しと育て直しを楽しめるか | **○** | `腕力36(+11/15)` の表示で「固定分＋加算／上限」がすぐ分かる。固定分が前回の値のおよそ半分であることも、数回で読み取れた。転生後はレベルが早く戻り、前を超えるのが気持ちいい。ただ「加算合計」にHPが入らず職と関係ない能力が入るので、良し悪しの判断が数字とずれる（減点）。チケットが余るので最終的に作業になる |
| ランダムな一般冒険者を雇い続ける意味／見た目・個体への愛着 | **△** | ネム姫には強い愛着が生まれた。ただその理由は「数値が高かった・改名した」で、**見た目は一度も見えなかった**（IDのみ）。転生のたびに勝手に見た目が変わり、エルフのウルザは `chr_m_nor` になった。中盤以降は所属枠と育成費用の都合で、新しく雇う動機は「罠対策の盗賊が欲しい」程度しかなかった |
| ステータススロットチケットの量 | **×（多すぎ）** | ギルドLv2の時点で21枚、1時間で151枚、8時間で**1185枚が未使用**。約200枚しか使っていない。チケットが「資源」として機能していないので、引き直しの判断の重みも消える |
| トレーニング・転生費用などゴールドの使い道 | **○** | 序盤は拡張（パーティ枠・候補枠・トレーニング場）で迷えて良かった。転生費用は 2000 → 5000 → 20000 → 80000G と段階的に上がり、手が届く範囲で納得できる。トレーニングは後半の費用の伸びが急で（Lv7→20で212回・48万G）、お金を一気に吸い込む先として機能していた。一方で、`train max` が全額を使うので派遣費が払えなくなる事故が起きた |

## 7. バグらしきもの・おかしな数値
1. **CLIがたまに終わらなくなる（CPU 98%で2分以上）**
   - 例1：`printf 'show adv_18\nshow adv_5\nwarehouse\n' | lune run tools/cli -- --save out/playtest/collector.json`（0:00:00、ウルザを雇った直後）。続けて単独で実行した `status` も止まった（timeout 20で rc=124）。直後にもう一度 `status` を実行すると0.08秒で終わった。
   - 例2：`printf 'open dng_castle\nopen dng_tower\nshow adv_218\nitems\n' | ...`（0:58:40）。150秒で強制終了したら何も保存されず、同じコマンドを1つずつ実行すると即座に終わった。
   - 再現は不安定。マシンの負荷は低かった（load 1.3）。
2. **転生中のエラーメッセージが雇用の文言になっている**
   - 転生の途中で `rebirth adv_13` → `✗ 雇用の途中です（candidates で確認、cancel でやめる）`（`candidates` を打つと「雇用していません」）。
   - 転生していない状態で `rb-choose cur` → `✗ 雇用を始めていません（hire）`。
3. **他人が装備中の品で `equip` すると「探索中は変更できません」**：探索していないブランに `equip adv_218 eq_187`（eq_187はパーティ2のアルドが装備中）で発生。ラガンに `equip adv_2595 eq_1319`（ウルザが装備中）でも同じ。正しくは「他の冒険者が装備中」などのはず。
4. **見た目維持ポーションの消費が一定しない**
   - ミラ：ポーション0個で `rebirth adv_13 keep` がエラーにならず通り、2000Gも引かれた。
   - ネム姫の1回目：ポーション1個で `rebirth adv_210 keep` → `rb-choose prev` しても1個のまま。
   - ウルザとミラの2回目、アルド、オスカー、エレナ、シエラでは確定時に1個ずつ減った。
   - フレイアとユリウスでは「ポーションがありません」で、正しく弾かれた。
5. **`status` の「（解錠技術が足りない）」と実際の挙動が合わない**：`status` で `罠の遺跡×19（解錠技術が足りない）` と出ても、`open dng_ruins` で19個すべて開く。解錠技術の拡張も `expansions` に出てこない。
6. **`open` が途中で止まった理由が出ない**：倉庫が満杯（300）になると「残りN個」とだけ出て止まる（例：3:31:35に騎士の古城を73個開けた時点で、水没神殿と霧の大森林の開封は何も表示されずに終わった）。
7. **`repeat` を設定しても、待機中のパーティは出発しない**：お金が足りず `go 1 dng_abbey` が失敗したあと `repeat 1 dng_abbey` は `✓ OK` になる。しかし `status` は「待機中 ／ 自動再派遣：呪われた修道院」のまま30分動かなかった。
8. **`trainquote` の見積もりと実際の回数がずれる**：`trainquote adv_218 10` は「34回 16580G」なのに、`train adv_218 max` は「32回（14960G）→ Lv9」で所持金切れ。見積もりと上限の扱いの違いは説明があると良い。
9. （数値の気になる点）雇用直後の候補（合計80〜140）は、初期メンバー（腕力14・技巧10程度）の2〜3倍ある。初期の4人がすぐ用済みになる。

## 8. 改善提案（優先順）
1. **見た目を見える化する**：ID ではなく「女性・エルフ・美形」のような説明、または簡単な特徴の文章を `show`・`rebirth`・`looks` に出す。`looks-choose` で prev 側も表示する。転生のたびに勝手に変わる仕様なら、それを最初に明示する。今のままでは見た目への愛着が育たない。
2. **チケットの配布量を1/5〜1/10に減らすか、チケットの別の使い道を作る**：今は1185枚余る。引き直しの重みを取り戻すほうが、厳選がずっと楽しくなる。
3. **引き直しの操作を楽にし、結果をキープできる仕組みを入れる**：`reroll 10`（条件付きで止まる）や「お気に入り枠を1つ固定できる」機能など。「良い結果が押し出されて消える」悔しさは残しつつ、連打の作業を減らす。
4. **加算合計を職に合わせて評価する／HPを含める**：例えば「主要能力の加算」「HP加算」を分けて出す、職の重みで★評価を付けるなど。ギフトにも効果の説明を付ける（`show` や候補の行に1行）。
5. **探索中でも装備変更・転生を予約できるようにする**：帰還時に反映する仕組み。合わせてエラー文言の取り違え（7章 2・3）を直し、`train max` に「派遣費ぶんを残す」選択肢を付ける。
