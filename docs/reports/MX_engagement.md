# MX-1 続けたくなる仕組みと体験の時刻表（2026-11-27）

このゲームが「飽きる前に刺激を与え、毎日戻りたくなり、やめても戻ってくる」作りになっているかを、理論と自動プレイの記録で調べた。本当に面白いかは人のテストプレイで確かめる。演出と分かりやすさは対象外（ゲーム内で確かめる）。

- 読んだもの：決定ログ（INDEX.md）、04・06章、`src/data` の時刻・量の値。
- 測ったもの：自動プレイ（1日の流れ、方針 greedy、MB-5 の後のデータ）を型ごとに seed 1・2 で最大の育成まで回し、出来事を全部記録した（`tools/balance/Experience.luau`）。
- 出来事の分け方：
  - **節目**：ダンジョンの解放、転生、ユニークの加入、パーティ枠・トレーニング場の拡張、転職、初めて出たレアリティ
  - **ごほうび**：レベルアップ、演出つきの開封、装備の更新、商人で買う、クエスト・ログインボーナスの受け取り、雇用、初踏破、ほかの拡張
  - **新しさ**：初めて起きたこと（各ダンジョン・各レアリティ・各ユニーク・各拡張の段・各転生の回数・各マップイベントの種類・初めての商人）
  - 留守の間に起きたことは、次のログインで見た時刻に数えた。

## 1. 人がゲームを続ける仕組みと、このゲームでの当てはめ

| 近い目標 | ゴールが近いほど人は急ぐ（目標勾配）。「あと少し」が見えると手を止めにくい | 次のダンジョン、拡張、転生、ギルドLv | 前半は強い、後半は弱い（§3） |

| 数分単位の目的 | 短い締め切りは今すぐ動く理由になる | マップイベント（5分ごと、出発は3分間） | 強い |
| 自分で選ぶ・上達・つながり | 自分で決めた、上手くなった、人と関わった、と感じるほど自分から続ける（自己決定理論） | ダンジョンごとの編成の工夫、日替わりで行き先を変える、他の人の馬車、フレンドボタン、紹介 | 中（つながりは薄い：D-065） |

罰を与えない設計（ログインが途切れても戻らない：D-155、受け取り箱に期限なし：D-176 など）は守れている。子どもの利用者が多い Roblox では、取り逃しの不安や途切れの罰で縛る仕組みは今後も使わない方がよい。

## 3. 空白と弱い所（大きい順）

1. **後半に新しいことがない（全部の型）。** 新しさの7〜10割が1週目に集まり、後半はほぼ0回。ライトは最後の約60〜80日、コアは約15日、ヘビーは約7日が「同じことの繰り返し」になる。後半の目標は「全員を最後の転生の上限まで」だけで、途中の手応えが見えない。
2. **ライトは長い停滞がある。** 節目のない日が最長33〜41日続き、後半のプレイで節目があるのは3〜10%。36分のプレイで毎回「何も起きなかった」になりやすい（D-299 で日数を110日にしたことの裏返し）。
3. **新しさが前に詰まりすぎている。** コアは全ダンジョンが4.6日で開き、拡張26段の大半も1週目に済む。「次はこれ」の楽しみを1週目で使い切る。
4. **デイリーを全部終えられない。** 1日3つのうち、ライト2.2・コア2.4しか達成できない。量がパーティ数に比例する（D-153）ため。習慣の柱である「毎日きっちり終わる」が成り立っていない。
5. **ごほうびの量が大きすぎて価値が見えにくい（理論上）。** 留守の宝箱はログイン1回で約300〜500個。量が多いほど1つの重みは下がる（慣れ）。開封のたびの期待の山は演出（M8-FX、未完了）に頼っている。
6. **週の山場がない。** ログインボーナス7日目のユニークが未定義（Q-025）で、毎回代わりの報酬になる。ユニークは3人だけで、今週の訪問者は2人の交代。集める楽しみがすぐ尽きる。
7. **最大の育成の後にやることがない。** D-199 で「後日」のまま。ここで多くの人が離れる。
8. **作業になりやすい所。** フレンドボタンは10分ごとに押さないとたまらない（1日12回）。後半のクエスト（雇用15・トレーニング125など）はパーティ数に比例して重くなる。
9. **日の区切りが英語圏の夕方に来る。** UTC 0時（日本の朝9時）は米国の夕方で、遊んでいる最中にデイリーが替わる。
10. **要確認：最初の宝箱。** 自動プレイでは最初の開封が約110秒（D-067・01章の目標は60秒以内）。自動プレイの開け方の都合かもしれないので、実機の誘導（D-244）で測り直す。

プレイ中のごほうびの間隔（90%点で約1分）と、戻った時の見返り（毎回届いている）は十分に強い。弱いのは「後半」と「毎日の締まり」。

## 5. 改善のループ

1. 弱い分類を1つ選び、直す案を出す（例：後半の新しさ → 後半に解放される仕組み・称号・ダンジョンの上位版など）。
2. 案を決定ログに入れ、実装またはデータを変える。数値だけなら `--set` で先に試す。
3. `lune run tools/balance` で体験スコアとバランスの成績表を同時に見る（体験を上げてバランスを崩していないか）。
4. 名前を付けて履歴に残す。
5. 区切りで人のテストプレイ（7日間の日記など）をして、点数の上下と人の感想が合っているかを見る。合わなければ指標や線を直す。
