# 10 テスト

## 1. 実行

```bash
lune run tools/test                 # 全テスト
lune run tools/test -- Combat       # ファイル名で絞り込み
lune run tools/check                # format 確認 + selene + 全テスト + マスターデータ検証
```

## 2. 書き方

- 置き場所：`tests/<Module>.spec.luau`。
- テストランナーは `tools/test` の自作の最小実装（`describe` / `it` / `expect`）。外部ライブラリに依存しない。
- **テスト名に決定IDを含める**（例：`it("D-005 戦闘不能者を除いて被弾率を按分する", ...)`）。
- 乱数を使う処理は固定シードで検証する。
- マスターデータの本番値に依存させたくないテストは、テスト用の小さなマスターデータを使う。

## 3. 必須のテスト

| 対象 | 内容 |
| --- | --- |
| Rng | 既知シードの出力列が固定値と一致（Roblox上でも一致することをM7で確認） |
| MasterData | 本番データが検証を通る／壊れたデータで失敗する |
| Formulas | 06章の各式（境界値：最低ダメージ、クリティカル上限、個体補正上限） |
| Combat / Events | 決定ID単位の振る舞い（行動順、被弾率の按分、支援の回復条件、罠の全滅） |
| Expedition | 同じ入力 → 同じログ。踏破・撤退・30ターン打ち切り |
| Game | コマンド失敗時に state が変わらない。advance の帰還・自動再派遣・オフライン復帰 |
| 統計テスト | 宝箱ランク・イベント種別などの抽選が、大量試行で指定確率に近い（許容誤差を明記） |

## 4. 決定IDのカバレッジ

`lune run tools/test -- --coverage-decisions` で、`docs/decisions/INDEX.md` の「実装対象」IDのうち、テスト名に一度も出てこないIDを一覧する。フェイズ完了時に確認する。

## 既知の問題：Lune 0.8.9 を同時に複数起動すると、まれに固まる（M6）

- 症状：Lune のプロセスを同時に4つ起動すると、約3割が起動直後（ゲームのモジュールを読み込む段階）で CPU 100% のまま止まる。
  1つずつ順に実行すると起きない。`print` だけの小さなスクリプトでは起きない。
- 調べたこと：止まったプロセスはメインのスレッドだけが空回りし、他のスレッドは待機。ゲームのコード（`src/core`）に入る前でも止まるため、ゲームの不具合ではない。
  Roblox 上のゲームには関係しない（Lune は開発用ツール）。
- 当面の運用：テキスト版・自動プレイ・テスト・シミュレーターは**同時に複数起動しない**（AI エージェントにも順に実行させる）。
- 根本対応の候補：Lune 0.10 以降へ上げる。ただし 0.10 は `init.luau` からの相対 `require` の解釈が変わる（`./X` → `@self/X`）ため、
  ツールの `require` の書き換えと、Roblox 向け変換（darklua）での確認が必要。
